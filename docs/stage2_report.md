# Отчёт: этап 2 — предметная логика

Этап выполнен по отдельному разрешению пользователя, без перехода к SQLite, новым формам и полноценной аналитике. Архитектура, формулы, шкалы и временная модель не изменены. Новые зависимости не устанавливались.

## Работа небольшими порциями

В AGENTS.md закреплено обязательное правило: короткий план по ТЗ, небольшие законченные порции, проверка и промежуточный отчёт после каждой, возможность пользователя скорректировать направление, остановка на границе разрешённого этапа.

Этап выполнен тремя порциями: ответы/шкалы (83 теста), модель оценки/индекс (118 тестов накопительно), временные модели (153 теста накопительно). После проверки дополнительных граничных случаев итог — 157 модульных тестов.

## Реализованные модули Domain

| Файл в src/healthtracker/domain/ | Назначение |
|---|---|
| __init__.py | Независимый пакет предметной логики |
| errors.py | DomainValidationError, без личных значений в сообщениях |
| answers.py | CognitiveAnswer и AnswerStatus: numeric, not_engaged, cannot_assess |
| scales.py | Семь числовых шкал версии 1, версии категориальных шкал, строгая проверка целых 0–10 и выбор известной версии |
| cognitive.py | CognitiveAssessment, версии трёх шкал и формулы, необязательный контекст, индекс версии 1 |
| time.py | UTC-нормализация, кандидаты локального часа, явный выбор смещения при повторении, календарная дата в переданном поясе |
| intervals.py | CognitiveInterval, SleepInterval, проверка пересечения сна, признак подтверждения длительного сна |
| measurement.py | CognitiveMeasurement: ответы, оцениваемый час, отдельные моменты создания/изменения |

Незаполненный ответ существует как None до создания определённой оценки. Ни одна модель не подменяет его специальным статусом. Специальный ответ не допускает даже числового нуля; numeric требует целое 0–10. Bool, строки и дробные числа отклоняются. Сохранённая модель оценки требует три определённых ответа; база и сохранение в этом этапе отсутствуют.

Все 77 числовых описаний скопированы из requirements.md дословно. Категории сложности занятия — «Лёгкая / Обычная / Сложная»; интенсивность симптома — «Слабая / Умеренная / Сильная». Определения неизменяемы, версии равны 1. SQLite-хранение определений относится к следующим этапам.

Индекс — равное среднее трёх чисел без округления и поправки на контекст. Специальный ответ в любой позиции даёт None для индекса, но не удаляет остальные числа. Неизвестные версии отклоняются, не заменяются текущими. При правке через создание новой неизменяемой модели версии сохраняются.

## Временные правила

- Модели принимают определённые моменты с поясом и нормализуют их в UTC; исходный пояс в модели не сохраняется.
- Наивное время не получает пояс автоматически. Для ввода местных часов есть отдельные функции: несуществующее время отклоняется, повторяющееся требует выбора смещения.
- Текущее время передаётся как обязательный аргумент now при создании интервала. Domain не читает часы компьютера. Это технический способ воспроизводимой проверки, не изменение продуктового времени.
- Начало когнитивного часа вычисляется из конца вычитанием 60 реальных минут в UTC. Конец не в будущем; совпадения и пересечения когнитивных часов допустимы.
- Дата когнитивного наблюдения — дата конца часа в явно переданном текущем поясе. Дата сна — дата пробуждения. UTC-моменты не меняются при смене пояса.
- Сон имеет положительную длительность, окончание не в будущем. Касание границ разрешено; пересечения, включая одинаковые интервалы, запрещены проверкой ensure_no_sleep_overlap. При редактировании будущий Application должен исключить старую запись по ID и выполнить проверку в транзакции.
- Более 16 часов даёт requires_confirmation=True. Сам интервал не блокируется; получение пользовательского подтверждения относится к будущей форме. Ровно 16 часов предупреждения не требует.
- Время создания/изменения отделено от оцениваемого часа. Время изменения не может предшествовать созданию. Правка не подменяет время создания временем наблюдения.

## Изменённая документация и границы

AGENTS.md, docs/development_plan.md и docs/architecture.md отражают разрешённый этап 2; README.md описывает текущую готовность и отдельный запуск модульных тестов. В pyproject.toml уточнено только описание проекта; зависимости не менялись. docs/requirements.md, docs/database.md, тексты шкал и отчёт этапа 1 не изменялись.

Новых таблиц, SQL, базы, форм, дневника, агрегаций, факторных сравнений, миграций и резервирования нет. Существующий интерфейс не изменён и не подключён к новым моделям. Сборка dist остаётся пробной сборкой этапа 1; её повторная сборка не требовалась для предметных модулей и не выполнялась на этапе 2.

Отклонений от ТЗ нет. Технические решения — неизменяемые dataclass-модели, enum-статусы и явно передаваемые часы/пояс — укладываются в утверждённые границы Domain. Следующий этап 3 не начинался и требует отдельного разрешения.
