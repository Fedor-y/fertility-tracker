## Порция 1: подключение базы и навигация

- Bootstrap создаёт существующий Database стандартного XDG-пути и передаёт его в ApplicationSession. При отсутствии базы явно создаётся только утверждённая схема версии 1. Известная схема проверяется и открывается существующим механизмом.
- ApplicationSession выполняет открытие/закрытие и выдаёт безопасное состояние для окна. Presentation не импортирует Infrastructure/sqlite3 и не содержит SQL.
- Для ошибок порта выделен application/errors.py. Infrastructure сохранила прежние импорты как ссылки на те же классы: логика существующих репозиториев и обработчиков не переписана.
- Несовместимая, повреждённая или занятая база приводит к явному сообщению и недоступности действий. Пустая база-замена и обходная миграция не создаются. Частные детали ошибки не показываются и не журналируются.
- Слева четыре раздела: Обзор, Аналитика, Дневник, Настройки. Переключение работает мышью и клавиатурой. В обзоре сохранён пустой ECharts и добавлены две основные кнопки и меню остальных записей.
- Кнопки форм/действия меню пока отключены: формы ещё не реализованы. Остальные разделы имеют явные временные состояния недоступности, без ложных данных и расчётов. Дневник ещё не отображает записи.
- Геометрия и состояние разворачивания сохраняются через QSettings; окно ограничивается доступной областью мониторов. Настройки графика/аналитики в QSettings не дублируются; остальные интерфейсные настройки этой порцией не реализовывались.
- Закрытие окна закрывает хранилище. При ошибке закрытие отменяется с сообщением; успешное завершение не имитируется.
- --smoke-test проверяет открытие хранилища и WebChannel, не сохраняет геометрию. Начиная с этой порции самопроверка использует стандартный XDG-путь так же, как обычный запуск; тесты подставляют временный XDG_DATA_HOME.

График не подключён к записанным наблюдениям, JavaScript не получает вычислений или SQL. Предупреждение о пустой области прямо сообщает, что данные базы пока не отображаются.

## Порция 2: когнитивная и физическая формы

Когнитивный диалог: три изначально пустых ответа, числа 0–10 и оба специальных статуса, точные описания Domain-шкал применённой версии, необязательные текст и категория сложности. Все три ответа обязательны; пустота не превращается в статус. Начало часа и индекс получает Application из существующего Domain. Возможен ретроспективный ввод.

Физический диалог: обязательная оценка без предвыбора, семь независимых категорий симптомов, необязательные интенсивности, уточнение Другого. Различаются перечисленные симптомы, явное отсутствие и неизвестность. При выборе симптома снимается подтверждение отсутствия; есть действие возврата к неизвестности. Длительность симптомов не добавлена.

Обе формы открываются главными кнопками. После commit ссылка «Открыть запись» возвращает сохранённую запись для просмотра и правки по ID. Постоянный доступ к истории после перезапуска будет в дневнике порции 7; сохранность самих записей и открытие по ID после повторного открытия Database проверены уже сейчас. Удаление остаётся порцией 7.

Application Observations координирует транзакции существующих репозиториев. Служебное время берётся из сессии; created_at, ID и версии при правке сохраняются. Повторная отправка успешно завершённого диалога игнорируется. Ошибка откатывает запись и сохраняет ввод. Сигнал успеха испускается после commit. Esc и закрытие окна с изменениями требуют подтверждения; Tab/стрелки/Ctrl+Enter работают. Формы прокручиваются на небольшом экране.

Местное время разрешает существующий Domain. Несуществующее время отклоняется, повторный час требует явного выбора UTC-смещения. Qt-редактор не угадывает DST. Микросекунды неизменённого сохранённого времени не теряются при правке других полей. Исходный пояс в базу не добавляется.

После когнитивного сохранения показывается необязательная кнопка физической оценки; её игнорирование ничего не создаёт. Стресс не предлагается.

## Порция 3: стресс и настроение

Реализованы два самостоятельных диалога, использующих прежние EntryDialog, ScoreChoice и MomentInput. Числовые оценки не предвыбраны; точные описания берутся из Domain-шкал версии 1 (или сохранённой версии при правке). Обязательны оценка и момент, допускается ретроспективный ввод, служебное время создания хранится отдельно.

StressDialog читает существующий SQLite-справочник причин через Application и DefinitionsRepository. Причин может быть несколько; комментарий необязателен. Список без выбранных причин означает, что причины не указаны. Отдельные состояния «причин нет» / «неизвестно» существующей моделью не предусмотрены и не добавлены.

Уточнение текущего задания пользователя: при любом сохранении стресса 0 причины и комментарий отсутствуют. Application нормализует вход для создания, перехода с положительной оценки и повторной правки нулевой записи. Прежний репозиторий сохраняет родителя и связи одной транзакцией; справочник остаётся неизменным. Дополнительного подтверждения очистки нет. При ошибке транзакции старые данные восстанавливаются, а заполненные поля формы не очищаются. Отмена формы ничего не записывает. Ранее сохранённые записи массово не переписываются.

MoodDialog использует отдельный MoodRepository. Он не создаёт и не требует физического состояния или стресса. Нулевое настроение — полноценное значение, а не отсутствие сведений.

В меню «Добавить» доступны Настроение, Стресс, Стресса нет. Сон, питание и спортзал остаются отключёнными. Быстрое действие вызывает тот же Application-сценарий save_stress, без отдельного SQL-пути; сохраняет текущий момент, явный 0 и пустые причины/комментарий. Повторные сигналы одного действия не создают дубликат до следующего открытия меню. Новое открытие меню позволяет добавить новое самостоятельное наблюдение. После ошибки повторная попытка доступна сразу.

Создание, просмотр и правка по ID работают для обеих форм. После commit ссылка «Открыть запись» открывает сохранённый ID, как в порции 2. При правке сохраняются ID, created_at, исходный момент при его неизменности и версия шкалы. До подтверждения commit сообщения об успехе нет. Повторная отправка завершённого диалога игнорируется. Формы используют прежние правила Tab/стрелок/Ctrl+Enter/Esc и подтверждения закрытия. Стресс после других форм не предлагается.

## Порция 5: питание

Выполнены только сценарии питания. MealDialog поддерживает создание, просмотр и правку по ID, календарную дату без времени, семь утверждённых категорий, одну или несколько позиций, их добавление и удаление до сохранения. Observations.save_meal использует прежние MealItem/MealRecord и MealRepository. В одной write-транзакции проверяются данные и повторы, сохраняются родитель и дочерние строки. Отказ/предупреждение завершают первую транзакцию без изменений, затем подтверждение запускает обычное сохранение заново. Неизменные дата/категория уже сохранённой записи не вызывают повторного предупреждения, Другое можно повторять без предупреждения. Изменение даты/категории требует новой проверки.

Предупреждение позволяет сохранить ещё одну запись, вернуться к форме или открыть существующую для просмотра/правки. При нескольких совпадениях выбирается запись по ID. Текущий ввод остаётся в исходном диалоге; автоматической перезаписи нет. Закрытие учитывает несохранённый дочерний редактор. При отказе и ошибках ввод сохраняется; успешный сигнал выдаётся после commit. Повторная отправка завершённой формы игнорируется.

Форма открывается из «Добавить → Питание», после сохранения доступно «Открыть запись». Спортзал остаётся отключённым. Длинные записи прокручиваются. ## Порция 7: полноценный дневник

Реализован раздел Дневник выбранной календарной даты. Он показывает семь прежних типов записей, без отдельной сущности вечернего отчёта и общей кнопки сохранения дня. Для каждой строки доступны краткое содержание, открытие существующей формы для просмотра/правки и подтверждаемое удаление. Подробные контексты, симптомы/интенсивности, причины/комментарии, состав и количество открываются в соответствующей форме; длинный список прокручивается.

ApplicationSession предоставляет Diary на том же Storage, что Observations. Все семь типов читаются в одной read_snapshot-транзакции. Привязка к дате использует текущий переданный пояс: конец когнитивного часа, момент физического состояния/стресса/настроения, пробуждение. Питание и зал используют исходную дату без преобразования. Временные записи упорядочены по реальному UTC-моменту, затем фиксированному порядку типов и ID при совпадении; смещения показываются рядом с местными часами, без выдуманных различий. События без времени находятся в отдельном блоке.

DiaryEntry и DiaryDay — неизменяемые представления уже прочитанных Domain-моделей, не новые таблицы/механизм хранения. Нули, специальные когнитивные ответы, неизвестные симптомы и подтверждённое отсутствие различаются. Пустой день не заполняется отрицательными отметками. Ошибка чтения показывается как ошибка, а не как подтверждённое отсутствие данных.

Главное окно открывает выбранный тип/ID через прежние формы и Observations. Успешный commit обновляет выбранный день; ID/created_at/версии и неизменённые UTC-моменты сохраняются. Если запись перенесена на другую дату, она исчезает из прежнего дня и появляется в новом. Отсутствующая запись не создаётся заново автоматически.

Из дневника можно добавить каждый из семи типов за выбранную дату. Питание и зал получают только дату. У моментальных форм при ретроспективном вводе календарь получает выбранную дату, а время остаётся пустым до явного ввода ЧЧ:ММ[:СС]. Календарь внутри формы можно изменить. Для сна выбранная дата задаёт пробуждение; начало вводится отдельно. Прежние формы не продублированы, для обычного добавления из Обзора сохранено текущее время по умолчанию. Разрешение UTC/DST выполняет существующий Domain, неоднозначный час требует выбора смещения, старые записи не переводятся в этот новый режим.

Удаление требует подтверждения с типом и выбранной датой, затем Diary.delete(kind, ID, confirmed=True) проверяет существование и вызывает прежний repository.delete в write-транзакции. FK-каскады удаляют дочерние позиции/связи, не каталоги и не остальные записи дня. Отказ ничего не меняет. Ошибка откатывает операцию и не показывает успех. Повторное удаление выдаёт RecordNotFound. После commit список обновляется; при ошибке последующей загрузки сообщение отдельно указывает, что удаление выполнено, но список не обновлён. Корзины, истории и экспорта нет.

Текущий пояс проверяется при открытии/обновлении страницы и раз в две секунды, пока она видима. Изменение показывает предупреждение и перегруппировывает дневник новым снимком; UTC и даты еды/зала не меняются. Ошибка графика не блокирует дневник. Реальные серии ECharts и аналитика не подключались.
