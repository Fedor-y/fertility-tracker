# Этап 7, часть 3 — BLACK HOLE UI

## Визуальный результат

Основной фон приложения и ECharts — #030303. Контролы #090909/#121212,
деликатные границы #1c1c1c, белый и серый текст. Навигация без внешней рамки,
активный пункт отмечен светлой вертикальной чертой. Подпись под брендом и нижний
служебный текст убраны из постоянной композиции. Общие токены применяются и к
остальным страницам, без перестройки форм и их бизнес-логики.

Обзор получил короткий заголовок без подзаголовка, одну компактную группу действий
и плоскую панель периода/режима/рядов. Основная кнопка «Оценить состояние» сохранила
доступное имя «Оценить когнитивное состояние». Физическое состояние и Добавить —
вторичные действия. Предложение дополнить оценку физического состояния осталось
короткой кнопкой в той же группе, вместо полноширинной строки.

Сообщение об успешном сохранении показывается на 5 секунд со ссылкой на запись.
После скрытия ссылка остаётся в меню Добавить → Открыть последнюю запись.
Этот пункт недоступен до первого сохранения и при недоступном хранилище.
Ошибки хранилища не скрываются как успешные уведомления.
Подтверждение актуального снимка больше не занимает постоянные строки Qt/HTML;
состояния обновления, устаревания и ошибки сохранены.

Диапазон/число календарных дат/неполнота периода доступны через tooltip выбора
периода. У графика одна компактная дата или диапазон; сводка осталась под ним без
карточки и отдельного заголовка. Сон, события и специальные ответы не удалены.
Карточки событий оформлены плоско, без ряда вложенных серых прямоугольников.

## График и ось времени

Включён единый набор визуальных правил для всех четырёх режимов:

- splitLine и minorSplitLine выключены; вертикальные markLine границ дат удалены.
  При смене режима и полной замене option сетка не возвращается.
- Главный ряд — когнитивный, если он включён и содержит значения; иначе первый
  включённый ряд со значениями. Светлая линия 2,4 CSS px, маркеры 7 px; Qt/Chromium
  сами применяют DPR. Остальные линии 1,2 px, отличаются яркостью, пунктиром и
  формой маркеров. При наведении точка немного увеличивается и подсвечивается.
- Заливка есть только у главного ряда и только у подготовленных Python-сегментов:
  вертикальный белый градиент alpha 0,12 → 0. Несколько рядов не создают сумму
  перекрывающихся заливок. smooth=false и connectNulls=false. Одна точка остаётся
  одной точкой, без фиктивного сегмента или заливки. Стресс без линий сохранён.
- В дневном режиме formatter берёт HH:mm из готовой Python-подписи тика, убирая
  дату и UTC offset. Целые трёхчасовые деления обычного дня показываются как
  00:00, 03:00, …, 21:00. Конечная полночь следующего дня отдельно не дублируется.
- В многодневных режимах используются краткие даты DD.MM, без повторений внутри
  даты. Плотность выбирается по ширине canvas, дополнительно hideOverlap=true.
  ResizeObserver обновляет плотность подписей, сохраняя текущий dataZoom.
- Координаты точек, min/max/step, исходные UTC-интервалы, зона, DST и сегменты
  не пересчитываются. Для DST-дня часы берутся из прежних готовых тиков, поэтому
  показанные часы могут отличаться от обычной последовательности 00/03/06.
  Полные времена/UTC offset/интервалы остаются в tooltip.

Подсказка — DOM с textContent, почти чёрный фон, тонкая граница, крупное белое
значение, вторичные дата/время и компактные детали. Состав сведений и действия
открытия исходных записей сохранены. UTC, начало интервала и версии доступны под
раскрываемой строкой «Подробности измерения»; основные значения/местное время и
компоненты видны сразу. Длинная подсказка прокручивается.

Сброс масштаба скрыт до изменения zoom/pan. Qt раз в секунду читает только визуальное
состояние локального ECharts через runJavaScript, не меняя WebChannel-протокол.
Сам сброс использует прежний запрос текущих параметров. Временная задержка появления
кнопки — до одного периода этого UI-таймера. Минимальная высота ChartView уменьшена
до 300 логических px, HTML canvas — до 300: на 200% дневная ось доступна без прежнего
лишнего сжатия/прокрутки. При раскрытых рядах/длинных событиях прокрутка сохраняется.

## Что требует ручной оценки

Нужна оценка пользователем общей композиции и читаемости на его мониторе:
насколько достаточно мягкой заливки и контраста вторичных рядов. Совпадающие ряды
по-прежнему полезно включать по отдельности. На узком окне длинная легенда имеет
пагинацию. В 200% доступная логическая область ограничена, развёрнутые параметры
и события могут требовать прокрутки. Нативные Qt-диалоги сохраняют семантические
значки предупреждения и особенности оформления окружения; они не перерабатывались.
Подписи факторов используют прежнюю терминологию; вычисления не менялись.
