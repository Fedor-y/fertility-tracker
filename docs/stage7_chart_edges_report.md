# Срочное исправление графика BLACK HOLE: края шкалы и zoom

## Причина и доказательства

Пользовательский скриншот в этом сообщении не приложен. На отдельном искусственном
наборе воспроизведена конкретная ошибка отображения; утверждение о точном состоянии
первоначального пользовательского окна без его снимка не делается.

**Настоящая ошибка непрерывности — dataZoom.filterMode="weakFilter".**
Zoom в промежуток 03:12–03:48 между соседними допустимыми измерениями
03:00 = 8 и 04:00 = 6 давал пустую область. Обе точки оказывались вне X-окна,
фильтрация удаляла их из обрабатываемого моделью ряда. Исходный payload/getOption
по-прежнему содержал сегмент, но его соединение больше не рисовалось. Это не
пропуск данных и не ошибка формулы. После filterMode="none" тот же сегмент виден
между краями окна; реальные точки остаются на своих координатах за пределами окна.
Новых измерений на границах zoom не добавлено: отсечение выполняется по геометрии
существующей линии. Непрерывность не расширена за подготовленные Python-сегменты.

До/после одного масштаба и одного набора:

- [Zoom между измерениями — до](/tmp/healthtracker-chart-edges/before/1/between.png)
- [Тот же сегмент — после](/tmp/healthtracker-chart-edges/after/1/between.png)
- [Края шкалы — до](/tmp/healthtracker-chart-edges/before/1/day.png)
- [Края шкалы — после](/tmp/healthtracker-chart-edges/after/1/day.png)

**Края Y:** прежние min=0/max=10 помещали измерения ровно на край grid.
На исходном canvas grid y=88, height=450: значение 10 попадало в y=88,
значение 0 — в y=538. Кроме того, xAxis.axisLine.onZero по умолчанию совмещал
нижнюю ось с нулевой линией. Это ухудшало различимость плоских участков на нуле.

Важно: гипотеза о полном обрезании Y-штриха обычным clipPath не подтвердилась.
Проверен реальный clipPath ECharts: для главной линии 2,4 px его y=86,8 и
height=452,4 — библиотека уже добавляла половину толщины сверху и снизу.
Поэтому исправление не выдаётся за устранение несуществовавшего полного Y-clipping.
Устранена доказанная фильтрация zoom, а положение крайних значений и оси улучшено
визуальными полями, чтобы не зависеть от рисования на самой границе.

**Настоящие разрывы:** в первом дне сохранены сегменты длиной 14, 2 и 3 точки:
00:00–13:00, 15:00–16:00, 21:00–23:00. В 14:00 специальный ответ без числового
значения; между 16:00 и 21:00 пауза больше прежних трёх часов. Domain также
разделяет почасовые сегменты при смене даты, неоднозначных совпадающих моментах
и обратном переводе часов в компактном режиме. Дневные медианы соединяются
только между соседними датами. Эти правила не менялись. Стресс остаётся без линий.

**Преобразование координат:** ошибок исходных X/Y-значений не обнаружено.
18 сравнений JSON (шесть видов запроса на трёх масштабах) подтвердили одинаковые
ID сегментов, исходные X и значения Y до/после. Изменилось только преобразование
Y в пиксели из-за визуальных полей и отсечение текущего X-окна.

## Исправление в renderer

Production-изменения ограничены resources/chart/chart_render.js:

- dataZoom.filterMode="none" сохраняет точки каждого готового сегмента при zoom/pan.
  Линии и scatter имеют clip=true: геометрия за X-окном не рисуется.
- Общая ось оценок: min=-0.5, max=10.5, interval=0.5, scale=false,
  boundaryGap=[0,0]. Formatter показывает только 0, 2, 4, 6, 8, 10.
  Неподписанные внешние поля — по половине единицы; отрицательных/сверхмаксимальных
  измерений нет, исходный допустимый диапазон по-прежнему 0–10. Такая же визуальная
  ось применена к значениям индекса в факторных диаграммах, без изменения расчётов.
- xAxis.axisLine.onZero=false переносит нижнюю ось на край области, отдельно от 0.
  X min/max/step и временные координаты не менялись, лишний boundaryGap по X не добавлен.
- При высоте grid 450 значения 0/10 теперь отстоят от его края на ~20,45 px.
  При узком окне поля уменьшаются пропорционально области, оставаясь внутри неё.
- connectNulls=false, smooth=false, отдельная line на каждый прежний сегмент.
  Заливка только главного ряда, origin=0; она не опускается до -0.5 и не соединяет
  разрывы. Верхняя/нижняя граница — визуальный запас, не изменение наблюдений.
- Главная линия остаётся белой 2,4 px, opacity=1 и с маркерами 7 px.
  Вторичные — 1 px, opacity=0,8, более тёмные серые оттенки, dashed/dotted/solid,
  разные формы маркеров 3,5 px с opacity=0,75. Точки не удалены. При выборе одного
  ряда он становится главным и рисуется отчётливо белым.

Чёрный фон, отсутствие сетки и существующая компактная панель сохранены.
Совпадающие по значениям компоненты закономерно лежат друг на друге; их координаты
не раздвигались искусственно. Для отдельного просмотра сохранены прежние флажки рядов.

## Сценарии и снимки

tests/manual/chart_edges_preview.py создаёт только временные SQLite/QSettings,
фиксирует тестовое время и подаёт обычные типизированные ChartQuery существующему
контроллеру. Панель периода в диагностическом сценарии не управляет запросами;
фактический диапазон отражён подписью графика. Пользовательское управление периодом
отдельно проверяется существующими UI-тестами.

Набор содержит 0, 10, несколько пересекающихся рядов, непрерывные фрагменты,
специальный ответ без числа, настоящий пропуск >3 ч, границы дней и одну точку.
Снимки: /tmp/healthtracker-chart-edges/{before,after}/{1,1.5,2}/.

## Сборка и ограничения

Новая onedir: **dist/stage7-chart-fix/healthtracker/**, Linux x86_64, текущий Arch Linux.
Рабочая **dist/stage7-part3/healthtracker/** сохранена отдельно.

```bash
.venv/bin/python -m PyInstaller --noconfirm \
  --distpath dist/stage7-chart-fix --workpath build/stage7-chart-fix \
  packaging/healthtracker.spec
./dist/stage7-chart-fix/healthtracker/healthtracker
```

Сохранять всю папку с _internal; пользовательские пути прежние, вне программы.
Универсальная переносимость между Linux-дистрибутивами не заявляется.
Ручная оценка человеком на его мониторе и физическое отключение монитора не проверялись.
Семантические разрывы при границе даты/спецответе/большом интервале намеренно остаются.
Междуточечный zoom может не иметь подписанного X-тика, если в очень узком диапазоне
нет прежних подготовленных делений; координаты при этом корректны, tooltip сохраняет
точное время измерения. Новые временные деления в этой правке не изобретались.

После проверки и сборки остановиться, следующую реализацию не начинать.

## Приёмка окончательной onedir

Новая onedir прошла прежний --check-bundle: status=ok, код выхода 0.
Копия /tmp/HealthTracker chart fix запускалась в настоящем Wayland из другого cwd,
без доступных исходников/.venv/системного Python, с пустым PATH, без сети и с каталогом
приложения только для чтения. Qt plugins, ресурсы и libpython загружены из _internal;
у Chromium renderer Seccomp=2, --no-sandbox не использовался.
Семь форм, ECharts, числовая Аналитика, создание/проверка/восстановление копии и
новый процесс с восстановленными данными/настройками прошли (по 15 записей семи типов).

Все 11 локальных ресурсов новой onedir совпадают с актуальными исходниками,
исполняемый файл совпадает с проверенной копией; SQLite-файлов в поставке нет.
Контрольные 3382 файла (61 защищённый исходник и файлы старой stage7-part3,
включая ссылки на библиотеки) не изменились. compileall и pip check прошли,
с прежним предупреждением недоступного pip-кеша. Новых зависимостей нет.
Прежнее сообщение завершения WebEngine-профиля в pytest и GBM → Vulkan осталось;
PyInstaller сохранил прежнее предупреждение необязательного QML-плагина.

Исправление завершено. Следующая реализация не начиналась.
