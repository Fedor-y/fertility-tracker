# HealthTracker — передача после этапа 6, части 2

Актуальный отчёт — [stage6_report.md](stage6_report.md), раздел части 2.

Одна проверенная копия реализована, автоматического запуска/страницы/кнопки нет.
Bootstrap внедряет SQLiteBackup в ApplicationSession; программный запрос:
`application.backups.create(BackupRequest(absolute_directory))` возвращает Future.
Application.backups содержит типы Request/Kind/Progress/Metadata/Result, BackupPort и
последовательную очередь BackupService. Infrastructure: backup_files.py и sqlite/backup.py.

Под прежним Database.exclusive ожидаются все принятые сессии. Разрешение содержит
SnapshotToken, confirm_safe(unchanged=True) после проверки сохраняет UUID/поколение
для read-only сценария; default confirm_safe/verify_access прежний. Backup API
использует отдельные worker-соединения. Ошибка цели не блокирует проверенный источник,
повреждённый/неизвестный источник остаётся RECOVERY_REQUIRED. После получения снимка
exclusive освобождается; проверка/публикация не мешают новым commit, которые не
считаются защищёнными старой копией. flock не освобождается на время снимка.

Пакет `<target>/<backup_id>/database.sqlite3` и `metadata.json` публикуется целиком
из `.pending-*` через renameat2 NOREPLACE после SQLite/FK/схемы/истории/хешей и fsync.
Метаданные: UUID копии, UTC/архивная дата, source UUID/generation, schema/checksum,
kind/size/file SHA/verified, checksum канонического JSON. inspect_backup независимо
проверяет пакет после перезапуска. UUID источника остаётся сеансовым, а не новым
постоянным идентификатором основной базы. Детали формата — architecture.md.

Рабочие файлы 0600, каталоги 0700, symlink/hardlink и перезапись существующего имени
запрещены. Ошибка новой операции сохраняет старый архив. Если носитель отказал и при
очистке, pending может остаться; он не считается пригодным и автоматически не убирается.
Event отменяет ожидание до критической последовательности; после начала Backup API
операция заканчивается успехом/ошибкой, а не ложной безопасной отменой.

ApplicationSession.close проверяет pending worker даже после освобождения exclusive;
MainWindow ждёт через Qt timer перед flush, затем прежнее завершение контроллеров,
worker и базы. Bootstrap finally дожидается worker без SQLite/WebChannel guard.

(49,46/50,15/49,59 с), после всех изменений. compileall/pip check/границы импортов
