# HealthTracker — предварительная модель SQLite

Это логическая модель для согласованного MVP, не исполняемый SQL-файл. Её начальная реализация находится в src/healthtracker/infrastructure/sqlite/schema.py. Этап 4, порции 1–7, подключает открытие/закрытие Database, все утверждённые формы и дневник выбранного дня через Application. Дневник — представление прежних таблиц; отдельной таблицы отчёта, корзины и истории нет. Схема версии 1 не изменена. В порции 8 Diary перешёл на существующий диапазонный метод репозиториев без изменения таблиц, индексов или миграций; результаты приёмки — stage4_acceptance.md. Нормативные правила: [requirements.md](requirements.md); границы компонентов: [architecture.md](architecture.md).

## 1. Соглашения

- ID основных записей — INTEGER PRIMARY KEY; внешние ключи — INTEGER.
- UTC-моменты — TEXT в одном ISO 8601 UTC-формате с фиксированной точностью. Дата без времени — TEXT YYYY-MM-DD.
- Оценки — INTEGER 0–10, категориальные статусы — TEXT с проверкой допустимых значений. Неизвестное значение — NULL, не 0.
- У пользовательских записей created_at_utc и updated_at_utc, отдельно от времени события. При правках created_at_utc не меняется.
- У составных связей возможен составной первичный ключ. Точные DDL и имена вторичных индексов определяются позднее.
- FK включаются для каждого соединения. Каждое соединение принадлежит своему потоку.
- Версии шкал и формул — ссылки на неизменяемые определения. Несовместимые версии не смешиваются молча.
- Дневные даты временных записей вычисляются в текущем поясе, не фиксируются как исходные даты. Исходный пояс не сохраняется.

### Обязательность и допустимые NULL

Во всех перечнях ниже обязательны все поля, кроме явно перечисленных в столбце NULL. Первичные ключи определены после сохранения, обязательные TEXT не пусты. Идентификаторы связей обязательны; отсутствие дочерних строк не заменяется строкой с пустым FK. Порядки — неотрицательные целые. Даты/моменты должны быть валидны и в едином формате; служебные времена генерирует приложение. Общие продуктовые проверки времени и шкал из requirements.md обязательны.

| Таблица | Единственные допустимые NULL | Внешние ключи и ограничения |
|---|---|---|
| cognitive_entries | learning_value/application_value/speed_value при специальном статусе; activity_description; activity_difficulty | Три scale_version_id → scale_versions.id, formula_version_id → formula_versions.id; статусы обязательны; numeric ⇔ число 0–10; прочие ⇔ NULL; интервал 60 минут; совпадение времени разрешено |
| physical_entries | Нет | scale_version_id → scale_versions.id; score 0–10; symptom_status из трёх значений; согласованность с дочерними симптомами |
| stress_entries | comment | scale_version_id → scale_versions.id; score 0–10; при правке положительного score в 0 comment очищается до NULL, связанные причины удаляются атомарно |
| mood_entries | Нет | scale_version_id → scale_versions.id; score 0–10 |
| sleep_entries | Нет | FK нет; start < end; запрет пересечения; нет UNIQUE по дате |
| meals | note | FK нет; категория из семи; дата обязательна; минимум одна позиция; нет UNIQUE дата/категория |
| meal_items | composition; quantity_text | meal_id → meals.id, удаление CASCADE; непустое name; UNIQUE(meal_id, position); caffeine_status обязателен, default unspecified |
| gym_entries | difficulty и difficulty_scale_version_id только при attended=0 | difficulty_scale_version_id → scale_versions.id; UNIQUE(entry_date); attended 0/1; при 1 оба поля обязательны и difficulty 0–10 |
| symptom_catalog | Нет | FK нет; PK id; UNIQUE(code); непустые code/name |
| physical_symptoms | intensity; detail | physical_entry_id → physical_entries.id CASCADE; symptom_id → symptom_catalog.id с запретом удаления используемой категории; составной PK; intensity только из трёх уровней |
| stress_cause_catalog | Нет | FK нет; PK id; UNIQUE(code); непустые code/name |
| stress_causes | Нет | stress_entry_id → stress_entries.id CASCADE; cause_id → stress_cause_catalog.id с запретом удаления используемой категории; составной PK |
| scale_versions | Нет | FK нет; положительная version; UNIQUE(scale_code, version); определение неизменяемо |
| formula_versions | Нет | FK нет; положительная version; UNIQUE(formula_code, version); определение неизменяемо |
| schema_migrations | Нет | FK нет; положительная version PK; UNIQUE(migration_id); checksum обязателен; регистрация атомарна изменениям |
| application_settings | Нет | FK нет; key PK; значение допустимо для известного ключа; отсутствие настройки — отсутствие строки, не NULL |

Все ссылки на scale_versions/formula_versions запрещают удаление используемых определений. Проверяется соответствие кода шкалы назначению поля. Для необязательного текста пустой ввод нормализуется в NULL; обязательное название из одних пробелов недопустимо. Типы остаются определёнными в разделах таблиц ниже. Это уточнение логической модели, не SQL-схема.

## 2. Основные таблицы

### cognitive_entries

| Поля | Тип / смысл |
|---|---|
| id | INTEGER, PK |
| interval_start_utc, interval_end_utc | TEXT, обязательны; конец одновременно время измерения |
| learning_status, application_status, speed_status | TEXT: numeric / not_engaged / cannot_assess |
| learning_value, application_value, speed_value | INTEGER 0–10 либо NULL по статусу |
| learning_scale_version_id, application_scale_version_id, speed_scale_version_id | INTEGER, FK scale_versions |
| formula_version_id | INTEGER, FK formula_versions |
| activity_description | TEXT, NULL допустим |
| activity_difficulty | TEXT, NULL либо категория Лёгкая / Обычная / Сложная |
| created_at_utc, updated_at_utc | TEXT |

Все три статуса обязательны. numeric требует число, остальные требуют NULL. Сохранённого статуса «не заполнено» нет; незаполненная форма существует только до сохранения. Для импорта/черновиков нельзя вводить обход этого правила — таких функций в MVP нет.

Конец не в будущем, начало ровно на 60 минут раньше по UTC. Пересечения и совпадения разрешены. Индекс производный, не обязательный сохранённый столбец; считается по версии только при трёх числах.

### physical_entries

id INTEGER PK; observed_at_utc TEXT; score INTEGER; scale_version_id INTEGER FK; symptom_status TEXT (listed / none_confirmed / unknown); created_at_utc и updated_at_utc TEXT.

Оценка обязательна. listed требует хотя бы один physical_symptoms; два других статуса запрещают дочерние симптомы. Оценка 10 не меняет symptom_status автоматически.

### stress_entries

id INTEGER PK; observed_at_utc TEXT; score INTEGER; scale_version_id INTEGER FK; comment TEXT NULL; created_at_utc и updated_at_utc TEXT.

Ноль — явное наблюдение, нет записи — неизвестно. При положительном score причины необязательны. Быстрое действие 0 не требует причин. По уточнению пользователя для порции 3 Application при любом сохранении score=0 передаёт пустой список причин и comment=NULL. Это сценарное правило, не изменение схемы и не массовая правка старых строк. Продолжительности нет.

При сохранении изменения положительного score на 0 в одной транзакции: обновить оценку и updated_at_utc, удалить все stress_causes этой записи, установить comment=NULL. Дополнительное подтверждение не требуется. ID, created_at_utc и scale_version_id сохраняются; stress_cause_catalog не изменяется. При сбое откатываются все части операции. Отмена формы не меняет строки. Нулевая запись остаётся явным наблюдением, а не отсутствием данных. Это правило перехода состояния, не поручение автоматически переписывать иные сохранённые записи.

### mood_entries

id INTEGER PK; observed_at_utc TEXT; score INTEGER; scale_version_id INTEGER FK; created_at_utc и updated_at_utc TEXT. Независима от остальных наблюдений.

### sleep_entries

id INTEGER PK; sleep_start_utc и wake_at_utc TEXT; created_at_utc и updated_at_utc TEXT. Длительность и местная дата пробуждения вычисляются.

Окончание позже начала и не в будущем. Пересечения проверяются внутри операции записи; касание границ допустимо. Уникальности по дате пробуждения нет. Более 16 часов требует подтверждения, не запрета. Автообъединения нет.

### meals

id INTEGER PK; meal_date TEXT; category TEXT; note TEXT NULL; created_at_utc и updated_at_utc TEXT.

Категория обязательна: шесть основных и Другое согласно requirements.md. Полей времени приёма пищи нет. Уникальности пары дата/категория нет: повтор после предупреждения допустим. Хотя бы одна дочерняя позиция обязательна.

### meal_items

id INTEGER PK; meal_id INTEGER FK meals; position INTEGER; name TEXT; composition TEXT NULL; quantity_text TEXT NULL; caffeine_status TEXT (contains / does_not_contain / unspecified); created_at_utc и updated_at_utc TEXT.

name непустое. Кофеин по умолчанию unspecified. position сохраняет порядок, уникален в пределах meal_id. Текстовое количество не парсится в дозы. Позиция принадлежит одному приёму; автоматической идентичности по названию нет.

### gym_entries

id INTEGER PK; entry_date TEXT UNIQUE; attended INTEGER (0/1); difficulty INTEGER NULL; difficulty_scale_version_id INTEGER NULL FK; created_at_utc и updated_at_utc TEXT.

При attended=1 сложность 0–10 и версия обязательны; при 0 сложность и её версия отсутствуют. Неизвестность — отсутствие строки, не attended=0. Времени тренировки нет.

## 3. Связанные таблицы

| Таблица | Поля и ключи |
|---|---|
| symptom_catalog | id INTEGER PK, code TEXT UNIQUE, name TEXT, display_order INTEGER |
| physical_symptoms | physical_entry_id INTEGER FK, symptom_id INTEGER FK; составной PK этих полей; intensity TEXT NULL; detail TEXT NULL |
| stress_cause_catalog | id INTEGER PK, code TEXT UNIQUE, name TEXT, display_order INTEGER |
| stress_causes | stress_entry_id INTEGER FK, cause_id INTEGER FK; составной PK |

Справочники содержат утверждённые категории, не пользовательский редактор категорий. Интенсивность симптома слабая/умеренная/сильная либо NULL. detail предназначено для текстового уточнения Другого; обязательность не вводится. Несколько разных симптомов и причин разрешены; одна категория не повторяется в одной записи.

Удаление physical_entries каскадно удаляет physical_symptoms, stress_entries — stress_causes, meals — meal_items. Каталоги не удаляются вместе с наблюдениями; используемые определения версий также защищены от удаления.

## 4. Служебные таблицы

| Таблица | Основные поля |
|---|---|
| scale_versions | id INTEGER PK; scale_code TEXT; version INTEGER; definition TEXT; created_at_utc TEXT; UNIQUE(scale_code, version) |
| formula_versions | id INTEGER PK; formula_code TEXT; version INTEGER; definition TEXT; created_at_utc TEXT; UNIQUE(formula_code, version) |
| schema_migrations | version INTEGER PK; migration_id TEXT UNIQUE; checksum TEXT; applied_at_utc TEXT |
| application_settings | key TEXT PK; value TEXT; updated_at_utc TEXT |

definition — неизменяемый документ (например JSON-текст) с утверждённым смыслом и описаниями. Это не исполняемый код. Приложение проверяет, что ссылка относится к нужной шкале/формуле, а не просто к существующему ID. Тексты версии 1 берутся дословно из requirements.md.

application_settings содержит только параметры графиков и аналитики. Геометрия, положение, разворачивание, масштаб интерфейса и путь копий принадлежат QSettings и не дублируются здесь. Каталог резервных снимков не должен зависеть от читаемости основной базы.

## 5. Проверки и транзакции

Ограничения строк (диапазоны, обязательность, сочетание статуса/числа, FK, уникальность зала) защищаются SQLite и Domain. Межстрочные правила (сон, хотя бы одна позиция, соответствие симптомов статусу) проверяются Application в транзакции. Будущая реализация должна исключать гонку между проверкой и сохранением; единственный пишущий экземпляр и согласованные транзакции обязательны.

Транзакционно: приём пищи со всеми позициями, физическое состояние с симптомами, стресс с причинами, составное редактирование, каскадное удаление, проверка и запись сна. При неуспехе rollback, форма сохраняет ввод. Повторная отправка одной формы не создаёт дубликат. Сохранение новой записи не заменяет старую автоматически.

## 6. Индексы и аналитические запросы

Предусмотреть индексы времени наблюдений и конца когнитивного часа, границ сна, даты/категории питания и FK дочерних таблиц. Не индексировать заранее все поля. Местные календарные границы преобразуются в UTC для отбора; группировка использует один текущий пояс на запрос. Питание и зал отбираются по введённым датам.

Когнитивные индексы, медианы, покрытие и сегменты не являются исходными таблицами. Расчёты Python, постоянный кэш в MVP не требуется. При изменении данных старые фоновые результаты инвалидируются.

Все запросы к разным таблицам в одном расчёте используют одну читающую транзакцию и одно соединение. Координатор согласует момент снимка с поколением данных; после чтения расчёт работает с неизменяемыми строками в памяти. Перед применением проверяются ID запроса, поколение и идентичность базы. Изменения/восстановление инвалидируют старые результаты; один ID запроса не заменяет проверку состояния данных.

## 7. Версия схемы и отказоустойчивость

Нумерованные миграции с контрольными суммами и проверенной отдельной копией перед каждой для существующей базы. Изменения схемы/данных и строка schema_migrations входят в одну транзакцию. После изменений и регистрации, до commit, проверить целостность, внешние ключи и ожидаемую версию. Успешной строка считается только после commit. При любой ошибке rollback возвращает и данные, и список миграций в прежнее состояние; повторный запуск проверяет фактическую схему. При отказе rollback/неопределённом commit запись блокируется, исходные копии сохраняются. Начальная схема новой базы также атомарна, но не требует копирования отсутствующей базы. Нарушающие атомарность операции не используются. Более новая неизвестная схема не открывается на запись.

Режим журналирования выбирается без ослабления надёжности; техническое допущение MVP — стандартное журналирование SQLite. WAL не обязателен. Любое резервирование открытой базы выполняется Backup API независимо от режима. Замена базы при восстановлении учитывает существующие вспомогательные файлы и выполняется только при закрытых соединениях; нельзя оставлять старый журнал рядом с новой базой как будто это единый комплект.

Корзины и истории правок нет. Повреждённый исходник сохраняется отдельно с его файлами, не перезаписывается восстановлением. Проверка целостности не доказывает истинность пользовательских наблюдений.

Полный порядок восстановления определён в requirements.md, раздел 14: проверенный временный кандидат, сохранение исходника, закрытие соединений, замена, повторное открытие/проверки и только затем работа. При восстановлении меняется поколение/идентичность базы. Генерации и каталог резервных копий — технические метаданные вне личных наблюдений; долговременный формат их хранения определяется при реализации и не дублирует пользовательские настройки.

## 8. Реализация этапа 3 и ограничения

- Фактический формат UTC: YYYY-MM-DDTHH:MM:SS.ffffffZ, всегда 27 символов и шесть цифр микросекунд. Календарная дата — YYYY-MM-DD. Типы таблиц STRICT; ограничения NOT NULL/CHECK/FK соответствуют разделам выше.
- Начальная миграция 0001_initial находится в migrations.py/schema.py. Порядок и контрольные суммы проверяются; применение DDL, seed-данных и регистрация версии — одна транзакция, итоговая проверка до commit. executescript не используется.
- Проверяется не только ledger, но и структура всех таблиц, индексов и триггеров. Существующая база проверяется read-only до открытия пишущих сессий. Обновление существующей схемы отклоняется MigrationBackupRequired до реализации защитного резервирования этапа 6 по новой нумерации пользователя; это не обход требования о копии.
- Время проверки передаётся Domain; создание/изменение не заменяет время наблюдения. При update время создания и применённые версии сохраняются, время изменения не возвращается назад. Неизвестная версия не подменяется версией 1.
- Все репозитории выполняют операции в Session. Savepoint откатывает весь агрегат при ошибке даже при перехвате исключения внутри внешней транзакции. Внешняя транзакция позволяет атомарно объединить несколько агрегатов.
- Симптомы и причины — внутренние связи родителя; позиции питания — внутренние строки агрегата в заданном порядке. При явной правке родителя дочерние строки могут пересоздаваться атомарно; их внутренние ID не являются API самостоятельных наблюдений. Их переданные служебные времена сохраняются. Независимые записи не затрагиваются.
- Читающий снимок привязан к идентичности открытой базы и поколению commit. Эти токены действуют в рамках текущего сеанса менеджера; при повторном открытии идентичность меняется. Неизменяемые результаты могут использоваться после закрытия снимка с проверкой актуальности. Постоянная маркировка для резервирования — последующий этап.
- В application_settings реализованы ключи visible_series, compact_mode, line_gap_hours, analytics_indicator. Это внутренние имена уже утверждённых параметров, не новые настройки. Окно и каталог копий сюда не записываются.
- Повреждение и неопределённый результат commit/rollback блокируют дальнейшую запись. Файл не удаляется и не заменяется автоматически. Восстановление и Backup API не реализованы на этапе 3.

Проверки и ограничения отражены в [stage3_report.md](stage3_report.md).
