# HealthTracker — полное техническое задание MVP

Статус: утверждённая продуктовая спецификация с явно выделенными техническими допущениями. Реализация требует отдельного разрешения. Этот документ — источник истины для функциональности и описаний шкал.

## 1. Цель и платформа

Локальное настольное приложение для длительного наблюдения за субъективным когнитивным состоянием, физическим самочувствием и возможными связанными факторами. Первая платформа — Arch Linux. Приложение не является сайтом, медицинским инструментом или объективным измерителем памяти, интеллекта и скорости обработки информации.

Приоритет: когнитивное состояние; физическое состояние; сон; зал, питание и стресс; настроение. Результаты описывают наблюдения, а не доказывают причины. Работа полностью локальная, без телеметрии, облака и обязательного интернета.

Ориентир использования — 3–4 короткие записи и подробное дополнение дневника вечером, без норм, принуждения и напоминаний. Вечерний отчёт не является отдельной сущностью.

## 2. Когнитивные записи

Три независимых ответа на одном экране: запоминание нового; воспроизведение и применение знаний; скорость мышления. Каждый — целое 0–10 или «Не занимался» / «Не могу оценить».

Сохранённая запись содержит три определённых ответа. Незавершённое поле остаётся незаполненным, не преобразуется в специальный ответ; сохранение блокируется с указанием поля. Отсутствие ответа, два специальных статуса и числовой ноль различны. Черновики не сохраняются. Предыдущие оценки автоматически не подставляются.

Индекс версии 1: I = (A + B + C) / 3, только при трёх числовых ответах. В остальных случаях индекс отсутствует, числовые компоненты сохраняются для своей аналитики. Контекст необязателен: описание и категория «Лёгкая / Обычная / Сложная». Он не корректирует индекс.

Оценивается последний час: время измерения — конец интервала, начало ровно на 60 реально прошедших минут раньше. Время создания отдельно. Пересечения разрешены, совпадение времени не запрещает запись, будущие измерения запрещены. Ретроспективный ввод не считается автоматически точным воспоминанием.

## 4. Стресс

Только добровольный отдельный ввод, без предложений после других форм и без напоминаний. Оценка момента 0–10 по силе внутреннего переживания, не по влиянию на работу.

| Балл | Описание версии 1 |
|---|---|
| 0 | Стресса не ощущаю |
| 1 | Едва заметное напряжение |
| 2 | Слабый стресс |
| 3 | Лёгкий, отчётливо заметный стресс |
| 4 | Умеренный стресс |
| 5 | Довольно ощутимый стресс |
| 6 | Выраженный стресс |
| 7 | Сильный стресс |
| 8 | Очень сильный стресс |
| 9 | Крайне сильный стресс, близкий к моему максимуму |
| 10 | Максимально сильный стресс, который могу представить для себя |

При положительной оценке необязательные предполагаемые причины: работа, учёба, отношения, финансы, здоровье, другое. Множественный выбор и необязательный комментарий. Отсутствие причины не блокирует сохранение. Причина — предположение пользователя.

«Стресса нет» одним действием создаёт самостоятельную нулевую запись на текущий момент без причин. Её время можно исправить. Нет записи — нет информации. Эпизоды, продолжительность и средняя интенсивность не собираются.

Уточнение пользователя для порции 3 этапа 4: при любом сохранении оценки стресса 0 причины и комментарий отсутствуют, включая создание и повторную правку нулевой записи. Application нормализует данные до передачи существующему репозиторию, в рамках той же транзакции. При сохранении правки существующей положительной оценки в 0 все её связанные причины автоматически удаляются, текстовый комментарий очищается (NULL). Дополнительное подтверждение очистки не требуется. Изменение оценки, удаление связей и очистка комментария выполняются одной транзакцией: при ошибке откатываются вместе, введённые данные остаются в форме. Запись сохраняет ID, исходное время создания и версию шкалы, становится явным нулевым наблюдением; время изменения обновляется. Справочник причин не удаляется. Отмена формы без сохранения не меняет базу. Это не преобразование отсутствующих записей в нули.

## 6. Ночной сон

Единый интервал с полными датами засыпания и пробуждения. Длительность — разность UTC-моментов. Привязка к местной дате пробуждения. Окончание позже начала; пересечения запрещены; несколько непересекающихся интервалов за дату разрешены. Более 16 часов — предупреждение с разрешением сохранения после подтверждения. Будущие завершённые интервалы запрещены. Исправление времени доступно. Дневного сна в MVP нет; интервалы автоматически не объединяются.

## 7. Питание

Одна запись — один приём пищи с одной или несколькими позициями. Обязательны дата, категория и название каждой позиции. Необязательны состав и количество каждой позиции свободным текстом; кофеин «Содержит / Не содержит / Не указано», по умолчанию неизвестно. Общая заметка необязательна.

Категории: завтрак, обед, ужин, перекус после завтрака, перекус после обеда, перекус после ужина, другое. Категория относится ко всему приёму пищи. Повтор основной категории за дату вызывает предупреждение с возможностью открыть существующую запись или подтвердить новую. «Другое» без предупреждения. Автоматического перезаписывания и блокировки повторов нет.

При проверке повтора редактируемая запись исключается из поиска. Сохранение без изменения даты и категории не требует повторного подтверждения уже принятого дубликата; при смене даты/категории проверка выполняется заново.

Времени еды нет вообще. Дата события отдельно от времени создания/изменения. Категории не являются часами или универсальными частями дня. Напитки и вода — обычные позиции. Неизвестный кофеин не означает его отсутствие. Не распознавать кофеин по названию, не вычислять дозу. Количество не преобразовывать в граммы, миллилитры, калории. Одинаковые названия не гарантируют одинаковый состав. Текстовые заметки не превращаются в оценки и не связываются автоматически с измерениями.

## 9. Время, версии и правки

Все точные моменты UTC; исходные пояс и смещение не сохраняются. Отображение и календарная группировка используют текущий пояс компьютера: когнитивная запись — дата конца часа, физическая/стресс/настроение — дата наблюдения, сон — дата пробуждения. Питание и зал используют введённую дату без преобразований.

Смена пояса сопровождается уведомлением и пересчётом графиков/аналитики. UTC не меняется; даты питания и зала остаются прежними. Несуществующее местное время отклоняется; для повторяющегося часа пользователь выбирает UTC-смещение. Каждый расчёт использует один согласованный снимок текущего пояса.

Записи можно создавать, изменять и удалять задним числом. Время создания не меняется при редактировании, время изменения обновляется. Корзины и истории правок нет; удаление подтверждается. Зависимые позиции и связи удаляются, справочники остаются. Двойное нажатие сохранения не создаёт вторую копию одной отправки.

Все шкалы имеют собственную версию 1, формула индекса — версию 1. Определения в SQLite неизменяемы. Старые записи сохраняют версии при редактировании; смысловые изменения создают новые версии. Несовместимые версии не объединяются незаметно. Python исполняет известные реализации; определения из базы не исполняются как код.

## 10. График

Большой график — центр обзора. Календарь выбирает произвольный диапазон включительно по датам. Быстрые периоды: день — сегодня; 7/10 дней — столько дат до сегодня включительно; месяц — текущий календарный месяц целиком; год — текущий календарный год целиком. Будущая часть текущего периода пустая и входит в размер диапазона для покрытия; период помечается незавершённым.

### Режимы

- Одна дата: местная полночь — следующая полночь, часы и реальные наблюдения. На переводе часов сутки 23/25 часов. Сон допускается отображать интервалом, обрезанным видимой областью.
- 2–7 дат: компактные равные участки дней, внутри шкала времени суток 00:00–24:00 и общая Y 0–10. Границы дней видны. Кнопка «График по часам» переключает на непрерывную реальную временную ленту с ночами и датами. Возврат в компактный режим доступен.
- Более 7 дат: дневные медианы, без почасовой кнопки. Для подробностей выбирается отдельный день или короткий диапазон. На длинных периодах подписи оси прореживаются до недель/месяцев без изменения исходной статистики.

### Данные и линии

Когнитивный индекс — основная яркая толстая линия. Физическое состояние — тоньше и приглушённее; по умолчанию включены обе. Настроение и стресс выключены по умолчанию, включаются пользователем. В дальнейшем составляющие индекса должны быть доступны как отдельные серии; в MVP обязательны их выбор в аналитике и сохранность данных, а отдельные линии компонентов на основном графике отложены.

Исходные числовые точки соединяются только внутри дня при интервале не более 3 часов включительно. Порог настраиваемый и влияет только на отображение. Через полночь соединений нет. Один замер — точка. Нет интерполяции, фиктивных точек и сглаживания. Соединение не является доказательством непрерывного изменения.

Долгосрочные когнитивные, физические и эмоциональные значения — независимые дневные медианы. Соединяются только соседние даты с данными. Стресс во всех режимах — реальные отдельные маркеры 0–10, включая нули, без дневной сводки и линий. Наложенные маркеры раскрываются общей подсказкой, не сдвигаются на выдуманное время.

Питание и зал не имеют почасовых точек. Подсказки показывают исходные значения, время/интервал, тип расчёта; дневные — медиану, минимум, максимум и число исходных наблюдений. После фиксации подсказки можно открыть исходную запись для правки; дневная сводка открывает соответствующие наблюдения, а не редактируется как запись.

Колесо масштабирует вокруг указателя, перетаскивание перемещает, сброс возвращает выбранный диапазон. Масштабирование не меняет календарный режим. Устаревший фоновый результат не заменяет актуальный.

### Совпадения времени и перевод часов

Все совпадающие по UTC когнитивные измерения сохраняются и участвуют в статистике по обычным правилам. Общая подсказка позволяет выбрать каждую запись; временные координаты не сдвигаются. Техническое правило отображения: между совпавшими точками не строится вертикальная линия; группа с несколькими наблюдениями показана отдельными точками и разрывает соединения с соседними группами, без выбора «последнего» значения и без усреднения для отрисовки.

В компактном дне повторяющийся местный час обозначается явно, оба UTC-момента сохраняются и различаются смещением в подсказке. Порядок наблюдений определяется UTC, не строковым порядком местных часов. Соединение через участок возврата местных часов не рисуется, чтобы не создать обратный ход линии; это техническое правило визуализации, а не удаление данных. Подробная лента сохраняет реальную длительность суток. Несуществующий час не заполняется искусственными точками.

## 11. Аналитика

### Расчёты

Для показателя и даты d: D(d) = медиана подходящих исходных числовых значений этой даты. Одна запись допустима. Для общего индекса подходят только полные записи; для компонента — все его числовые ответы независимо от полноты индекса.

Для множества S дат с данными: основная сводка M = median(D(d)); дополнительная A = sum(D(d)) / |S|. Каждый день имеет одинаковый вес. Минимальная и максимальная дневные медианы показываются с датами; это не объективные лучшие/худшие дни.

Сводка периода (M, A, минимум, максимум) доступна только при |S| ≥ 7. При меньшем числе — дневные точки, количество данных, покрытие, пояснение; без агрегированной сводки. Диапазон короче семи дат автоматически не достигает порога.

Покрытие = дни с подходящими данными / календарные дни диапазона × 100%. Всегда показывать числитель и знаменатель, например 9 из 14 — 64%. Число измерений и дней доступно независимо от сводки. Покрытие зависит от выбранного показателя и не означает полноту измерения каждого дня.

Сравнение: текущая неделя с предыдущей, месяц с предыдущим, два произвольных диапазона, в том числе разной длины. Для незавершённого периода — такая же прошедшая часть предыдущего; прошлый месяц ограничивается его последним днём. Неделя начинается в понедельник. Разница Δ = M первого − M второго в пунктах, только если оба имеют ≥ 7 подходящих дней. Всегда видны границы, покрытие и объём данных. Процентное «улучшение способностей» запрещено.

Примеры: 6, 8, 7 дают индекс 7; три нуля дают 0; специальный ответ оставляет индекс отсутствующим. Дневные индексы 2, 4, 8, 10 дают медиану 6. Дневные медианы семи дат 2, 4, 6, 6, 8, 8, 8 дают M = 6 и A = 6. При шести датах сводка скрыта.

### Сон

Точечный график: X — длительность ночного сна в часах по UTC; Y — обычная дневная медиана индекса; точка — дата пробуждения. Исключать даты без сна, без подходящей медианы, с несколькими интервалами сна, с хотя бы одним полным когнитивным измерением, чей оцениваемый час начался до пробуждения. Начало ровно в пробуждение допустимо. Обычная медиана не меняется, альтернативной нет. Показать число использованных и исключённых дат и причины; пересекающиеся причины не удваивают количество дат. Без прогнозной линии и причинных выводов.

### Спортзал

Сравнить дневные медианы дат с подтверждённым «Был» и «Не был». Неизвестные дни не включать. Показать дневные точки, медиану и количество каждой группы. При < 5 дат в любой группе — «Мало наблюдений для сравнения», расчёты не скрывать. Пустая группа не имеет медианы; разница не вычисляется. Сложность — только в подсказке, не группировка. Порог 7 дней общей сводки к этому инструменту не применяется. Время тренировки неизвестно: нет утверждений об эффекте «после» неё.

Дополнительных факторных сравнений стресса, питания, кофеина, физического состояния и настроения в MVP нет.

### Согласованность расчёта

Один расчёт читает все нужные таблицы через одно соединение в единой читающей транзакции. После получения исходного снимка транзакция может завершиться, а расчёты продолжиться по неизменяемым данным в памяти. Чтение согласуется с фиксацией поколения данных. Результат применяется только при совпадении поколения основной базы и актуальности запроса; проверка повторяется непосредственно перед передачей и применением в графике. Замена базы при восстановлении создаёт новое поколение, даже если числовые ID записей совпали.

## 12. Интерфейс

Левая панель: Обзор, Аналитика, Дневник, Настройки. Обзор: управление периодом и слоями, две основные кнопки «Оценить когнитивное состояние» / «Физическое состояние», большой график и краткая статистика по порогу. Меню «Добавить»: настроение, стресс, «Стресса нет», сон, питание, спортзал. Формы — диалоги.

Tab — последовательный переход, стрелки — выбор, Ctrl+Enter — сохранение, Esc — закрытие. Несохранённые изменения требуют подтверждения. Из дневника используется выбранная дата, прошлое время вводится явно.

Новые моментальные формы и конец нового когнитивного часа используют текущее время по умолчанию. При редактировании показываются сохранённые дата и время. Выбор прошлой даты не сопровождается скрытой подстановкой часа. Оценки не предвыбираются; изменение времени доступно до сохранения.

Монохром: чёрный, графит, серый, белый; различия толщиной, яркостью, штрихом и маркерами, не только оттенком. Читаемый контраст, минимальная сетка, чистая типографика. Минимальная целевая область 1000×700 логических пикселей; начальная до 1280×800 по экрану. На меньшем экране прокрутка, без недоступных элементов. Проверка 100/150/200%; окно не восстанавливается за отключённым монитором.

Нет данных — пустая область с пояснением, без нулевой линии. Мало дней — пояснение порога. Ошибка графика не блокирует формы. Ошибка сохранения не теряет ввод и не показывает ложный успех.

## 14. Хранение, миграции, резервирование

База отдельно от программы: $XDG_DATA_HOME/healthtracker, иначе ~/.local/share/healthtracker. Обновление/переустановка программы не удаляет её. Пароля и шифрования нет, доступ только владельцу Linux, включая копии и вспомогательные файлы. Никаких внешних сервисов, CDN, сетевой отправки и телеметрии.

Миграции последовательные и нумерованные. Перед каждой — отдельная проверенная резервная копия, иначе миграция не начинается. Изменения схемы/данных и регистрация версии выполняются в одной транзакции. После применения изменений, но до commit, проверяются целостность SQLite, внешние ключи и ожидаемая версия схемы. Любая ошибка вызывает rollback; обычная работа не разрешается до проверки восстановленного состояния. При отказе rollback или неопределённом результате commit база блокируется для записи и сохраняется для восстановления. Неизвестная более новая схема не открывается для записи. Операции, нарушающие атомарность, в миграции MVP не допускаются. Начальная схема новой пустой базы создаётся транзакционно; это исключение из необходимости копировать ещё не существующую пользовательскую базу.

Копирование через sqlite3.Connection.backup(). Автоматически при запуске, если за текущую дату не было успешной автоматической копии; после изменений — когда с предыдущей успешной автоматической копии прошло ≥ часа. Если час ещё не прошёл, запланировать копирование на достижение порога при работающем приложении. Ручная копия доступна. Службы при закрытом приложении нет.

Только автоматические копии учитываются часовым ограничением и условием «успешная автоматическая копия за текущую дату». Успешная ручная или защитная копия, в том числе предмиграционная и перед восстановлением, не сдвигает автоматический срок, не удовлетворяет условию даты и не отменяет ожидающую автоматическую задачу. Неудачная копия любого типа не меняет отметки успешности. Тип снимка фиксируется в метаданных и не переопределяется ради расписания. Назначение, расписание и правила хранения автоматических, ручных и защитных копий разделены; обязательная защитная копия не заменяется уже имеющейся автоматической или ручной.

Сначала временный снимок, затем проверка целостности, внешних ключей и схемы, регистрация успешного снимка, и только затем ротация. Неудачная новая копия не удаляет старые.

Одновременно выполняется только одна задача резервирования любого типа; остальные запросы ожидают или объединяются без потери обязательной предмиграционной копии. Для получения точного поколения снимка координатор не допускает commit изменений основной базы на время получения снимка Backup API и фиксации его поколения. Чтение и ввод в формы могут продолжаться; сохранение ожидает. Пауза должна быть ограниченной, при длительном ожидании показывается состояние операции. Это техническая организация согласованности, не отдельная пользовательская функция.

Метаданные снимка содержат идентификатор базы, поколение защищённых данных, тип, UTC-время создания, зафиксированную архивную дату, версию схемы и статус проверки. Изменения после снимка получают следующее поколение и остаются ожидающими копирования. Проверка/регистрация снимка не объявляет защищёнными более новые изменения. Метаданные доступны независимо от основной базы.

По умолчанию отдельная папка backups в каталоге данных; другой каталог выбирает пользователь. 24 последних автоматических снимка и представители 30 последних дат, когда копии создавались: последний успешный снимок каждой даты. Один файл может входить в обе группы, удаление лишь вне обеих. Дата архива фиксируется при создании; UTC-момент также сохраняется. Пропущенные дни не заполняются. Ручные, предмиграционные и защитные копии восстановления ротацией не удаляются.

После смены каталога старые копии автоматически не перемещаются и не удаляются. Ротация действует только в текущем каталоге и только для распознанных управляемых снимков. Произвольные файлы не удаляются. Смена каталога сериализована с резервированием: уже начатая операция завершается или безопасно отменяется до переключения; новый запрос использует новый путь.

При недоступности каталога работа с исправной базой продолжается с постоянным предупреждением и временем последней копии. Путь не меняется автоматически. Миграции и восстановление, требующие защитной копии, блокируются. Носитель, не обеспечивающий доступ владельцу, не считается пригодным.

Восстановление полностью заменяет базу без объединения: проверить копию и совместимость, показать дату, запросить подтверждение, остановить изменения и фоновые задачи, сохранить исходную базу отдельно, закрыть соединения, безопасно заменить. При сбое исходник сохраняется. Повреждённый файл не уничтожается: сохранить комплект исходных файлов после прекращения доступа, не выдавая его за исправную копию. Автовосстановление запрещено. При повреждении остановить запись, миграции и ротацию, предложить восстановление; не подставлять молча пустую базу.

### Последовательность восстановления

1. Подготовить независимый временный файл-кандидат на файловой системе основной базы, не изменяя выбранную пользователем копию. Проверить SQLite, внешние ключи и совместимость схемы; показать дату и запросить подтверждение.
2. Остановить новые операции и дождаться текущих задач. Для исправной основной базы создать и проверить отдельную защитную копию через Backup API. Закрыть все соединения. При повреждении после прекращения доступа сохранить исходный комплект с существующими вспомогательными файлами, не пытаясь объявить его исправной копией.
3. Сохранить исходный комплект отдельно от рабочего пути; его нельзя перезаписывать файлом-кандидатом. До замены убедиться в успешности защитного сохранения. Старые журналы не должны оставаться рядом с новой базой как её журналы.
4. Повторно проверить подготовленный кандидат и выполнить замену в рабочем пути. Состояние операции должно позволять при следующем запуске обнаружить незавершённую замену, не создавая пустую базу.
5. Повторно открыть заменённую базу в режиме проверки, проверить целостность, ключи и схему. Для поддерживаемой старой схемы выполнить обычные защищённые миграции; неизвестная новая схема недопустима.
6. Только после успеха обновить идентичность/поколение данных, сбросить старые фоновые запросы и состояния экранов и разрешить обычную работу. QSettings не менять.

При любом сбое сохранить защитные и исходные файлы, остановить запись и показать ошибку, не сообщая об успешном восстановлении. Если безопасно возможно вернуть исходный рабочий комплект, это технический откат операции, а не автоматическое восстановление архивной копии. При неопределённом состоянии не предпринимать разрушительных повторных действий. Внедряемый протокол замены должен тестировать отказ на каждой границе, включая повторное открытие и перезапуск после аварии.

## 15. Диагностика и поставка

Ограниченный локальный журнал: версия программы, код операции, тип ошибки, очищенные технические сведения. Запрещены личные тексты, оценки, SQL-параметры и сообщения WebChannel. Понятные сообщения и сохранение формы при отказе.

Разработка в виртуальном окружении, без установки в системный Python. PyInstaller onedir и ярлык меню Linux, не onefile. Ручное обновление при закрытой программе заменой её папки, без базы. Версии зависимостей фиксируются после проверки Python, PySide6, WebEngine, WebChannel, локального ECharts и сборки на Arch Linux.

## 16. Приёмка и обязательные тесты

- Все виды записей создаются/исправляются/удаляются, прошлые даты поддержаны; шкалы версии 1 дословны.
- Когнитивная форма требует три ответа; незаполненность не становится статусом; специальные ответы не становятся нулями.
- Верны индекс, дневные медианы, равный вес дней, покрытие, пороги 6/7 и 4/5, разница периодов.
- Все режимы графика, 3 часа ровно/больше, полночь, пропуски, стрессовые нули, независимые физические и эмоциональные сводки проверены.
- Пересечения когнитивных интервалов допустимы; сон не пересекается; 16 часов и превышение, несколько снов и исключения аналитики проверены.
- Проверены смена пояса, 23/25-часовые дни, повторяющееся/несуществующее время и неизменность дат питания/зала.
- Повтор питания предупреждает, зал уникален, составные операции и удаления транзакционны.
- Проверены миграции, включая отказ итоговой проверки целостности/ключей/версии; работа с повреждённой или новой неизвестной схемой блокируется.
- Проверены Backup API открытой базы, проверка до ротации, ошибка новой копии без удаления старых, принадлежность двум архивным группам и восстановление с отказами.
- Проверена недоступность копий и отсутствие утечки личных данных в журнал.
- Форма не теряет ввод при ошибке. Устаревшие результаты, в том числе завершённые в обратном порядке, не заменяют актуальный график.
- Проверены WebChannel, безопасный вывод текстов, отказ графика без отказа дневника, клавиатура и масштабы.
- Onedir запускается офлайн на Arch Linux; ручное обновление сохраняет данные.
- Проверены атомарность регистрации миграции и rollback при отказе каждой проверки до commit; повторный запуск не принимает неуспешную миграцию за завершённую.
- Один расчёт использует согласованный снимок всех таблиц; несовпадение поколения или базы не допускает применение результата.
- Параллельные запросы резервирования сериализованы; новые изменения не помечаются защищёнными старым снимком. Смена каталога не удаляет/перемещает старые копии.
- Восстановление тестируется с отказами до/после замены, повторного открытия и аварийным перезапуском; исходные файлы сохраняются.
- Совпадающие измерения и повторный местный час не создают ложных линий или выдуманных временных координат. Поведение новых/редактируемых форм проверено.
- Ручные и защитные копии не меняют часовой/дневной автоматический график; только успешные автоматические обновляют его отметки. Ротация не удаляет ручные и защитные копии.
- Сохранение правки стресса с положительного значения на 0 без дополнительного подтверждения атомарно удаляет причины и очищает комментарий; отказ транзакции возвращает прежнее состояние, отмена формы ничего не сохраняет.

Тестовые базы искусственные, не личный дневник. Нормативы памяти/времени запуска пока не назначены: измерить на целевой машине, длительные задачи не должны замораживать интерфейс.

## 17. За пределами MVP

Облако, мобильная версия, многопользовательский режим, медицинские выводы, объективные когнитивные тесты, автоматические рекомендации, сложная статистика/прогнозы, напоминания, дневной сон, другие активности и спортивный дневник, калории/БЖУ, каталог/распознавание/фото еды, шаблоны и копирование питания, счётчик воды, автоматический кофеин, дополнительные факторные сравнения, экспорт CSV/JSON, пароль/шифрование, корзина/история правок. Перенос — резервирование и восстановление SQLite.

## 18. Технические допущения, не новые функции

- Один профиль и одна основная база. Второй экземпляр не пишет параллельно.
- Будущие моменты физических/эмоциональных/стрессовых наблюдений и будущие даты питания/зала запрещены.
- Интервалы сна полуоткрытые: окончание одного может совпасть с началом другого.
- Специальный ответ разрывает соответствующую исходную серию; соединение поверх явной неопределённости запрещено.
- Производные значения не округляются до агрегации; отображаются обычно с двумя десятичными знаками, оценки — целыми.
- При равных экстремумах доступны все даты. Постоянный кэш аналитики не нужен.
- Уточнение «Другое» у симптома допускается, но не обязательно.
- Файл базы — healthtracker.sqlite3. Выбор конкретных совместимых версий библиотек — первый технический этап.

Неделя с понедельника, правила графических совпадений, точность отображения, отсутствие постоянного кэша, pytest-qt и способ журналирования SQLite являются техническими допущениями, а не новыми пользовательскими функциями. Отложенные линии когнитивных компонентов не исключают обязательную компонентную аналитику MVP.
