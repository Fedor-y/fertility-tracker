# HealthTracker

Локальное desktop-приложение для Arch Linux x86_64: дневник состояния,
аналитика и интерактивные графики в минималистичном чёрном интерфейсе BLACK HOLE.
Данные хранятся в SQLite на компьютере пользователя; приложение работает без сервера.

## Возможности

- Семь журналов: когнитивное и физическое состояние, настроение, стресс, сон, питание и спортзал.
- Дневник с просмотром, редактированием и удалением записей.
- Обзор с локальным ECharts: семь рядов, четыре режима, zoom/pan, слои и сохранение предпочтений.
- Плавные монохромные линии через полночь с сохранением настоящих пропусков.
- Аналитика: сводки, дневные значения, покрытие и сравнения периодов.
- Ручное создание проверенных резервных копий через SQLite Backup API и восстановление с перезапуском.

Стек: Python 3.14, PySide6/Qt Widgets, Qt WebEngine, Qt WebChannel, ECharts 6 и SQLite.
Целевая платформа — **Arch Linux x86_64, Wayland**, Chromium sandbox включён.
Проект — рабочий прототип; переносимость на другие дистрибутивы не гарантируется.
Ротация, расписание копий, облачная синхронизация и экспорт пока не реализованы.

Последняя подтверждённая регрессия: **1200 passed**, 7 прежних предупреждений.
Визуальные проверки выполнены при 100%, 150% и 200%.
Подробнее: [архитектура](docs/architecture.md),
[текущая передача](docs/handoff.md),
[отчёт о графике и сборке](docs/stage7_smooth_chart_report.md).

## Запуск подготовленного окружения

Из папки проекта:

```bash
.venv/bin/python -m healthtracker
```

Обычный запуск теперь создаёт отсутствующую базу утверждённой версии или открывает уже известную схему в стандартном XDG-каталоге. При несовместимой, повреждённой или занятой базе окно показывает ошибку; пустая замена не создаётся. Геометрия и разворачивание сохраняются в QSettings, настройки графиков туда не записываются.

Самопроверка открывает базу и окно, проверяет локальный график и двусторонний WebChannel, печатает технический результат и закрывается. Геометрию она не изменяет:

```bash
.venv/bin/python -m healthtracker --smoke-test
```

Нужен доступ к графическому сеансу Linux. Ошибка подключения к Wayland/X11 из ограниченной среды не означает, что отсутствует PySide6. Не отключайте Chromium sandbox для обычного запуска.

## Воспроизведение окружения

Проверено: Python **3.14.7**, PySide6/Qt **6.12.0**, ECharts **6.0.0**, PyInstaller **6.22.3**. Полный набор Python-зависимостей закреплён в requirements-dev.lock; ECharts уже находится в ресурсах проекта. Для первоначального скачивания Python-зависимостей требуется сеть, для запуска — нет.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir -r requirements-dev.lock
.venv/bin/python -m pip install --no-build-isolation --no-deps -e .
```

Команды установки выполняются только внутри `.venv`; системные пакеты не меняются. Версии, отличные от проверенных, требуют повторной проверки совместимости. Файл lock закрепляет версии, но не является хешированным архивом пакетов.

## Проверки первого этапа

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m pip check
.venv/bin/python -m compileall -q src tests packaging/launcher.py
```

Тесты этапа 1 запускают настоящий Qt WebEngine в текущем графическом сеансе: проверяют локальную область графика, готовность ECharts/WebChannel, ограничения ресурсов, отказ навигации в сеть и сообщение об ошибке загрузки.

Модульные тесты этапа 2 запускаются отдельно без графического сеанса:

```bash
.venv/bin/python -m pytest tests/unit -q
```

Они проверяют точность всех описаний шкал относительно ТЗ, ответы и специальные статусы, индекс, версии, UTC-интервалы и сон. Время проверки передаётся в модели явно; Domain не обращается к системным часам, Qt или SQLite.

Проверка предметной логики и SQLite без графического сеанса:

```bash
.venv/bin/python -m pytest tests/unit tests/integration -q
```

SQLite-тесты используют искусственные файлы во временном каталоге pytest, не личную базу. Проверяются 16 таблиц, CRUD, составные операции, откаты, снимки и повторное открытие.

## Границы SQLite на этапе 3

`infrastructure/sqlite/database.py` предоставляет явное создание через `Database(path).initialize()`, транзакционные сессии `write()` и согласованные `read_snapshot()`. Репозитории семи видов записей доступны в сессии; все их операции завершаются внутри внешней транзакции. Результаты чтения содержат ID и неизменяемую модель Domain. Проверка `is_current(token)` выполняется после закрытия снимка.

Путь по умолчанию: `$XDG_DATA_HOME/healthtracker/healthtracker.sqlite3` либо `~/.local/share/healthtracker/healthtracker.sqlite3`. Сам расчёт пути ничего не создаёт; при обычном запуске bootstrap явно вызывает ApplicationSession.open(). Файлы ограничены владельцем. Вторая пишущая копия приложения отклоняется файловой блокировкой.

Поддерживается начальная миграция `0001_initial` и повторное открытие совпадающей схемы. Существующая база сначала проверяется read-only. Обновление старой схемы **заблокировано до защитного резервирования этапа 6** по новому порядку пользователя; обходного флага нет. Неизвестная новая/изменённая схема или повреждённый файл не заменяются пустой базой. Автоматические копии и восстановление ещё не реализованы.

При наличии уже установленного `bwrap` можно повторить проверки с отдельным сетевым пространством без доступа к сети, не меняя сеть компьютера:

```bash
bwrap --unshare-net --dev-bind / / -- .venv/bin/python -m pytest -q
bwrap --unshare-net --dev-bind / / -- .venv/bin/python -m healthtracker --smoke-test
```

Эти команды зависят от разрешённых в системе пространств имён и доступа к локальному дисплею. Приложение само блокирует удалённые ресурсы WebEngine; профиль не сохраняет cookies и локальное хранилище.

## Рабочая Linux onedir — исправление графика BLACK HOLE

Целевая система — Arch Linux x86_64 с Wayland. Chromium sandbox сохраняется.

```bash
.venv/bin/python -m PyInstaller --noconfirm \
  --distpath dist/stage7-smooth --workpath build/stage7-smooth \
  packaging/healthtracker.spec
./dist/stage7-smooth/healthtracker/healthtracker
```

Для запуска Python/.venv/IDE не нужны. Сохраняйте всю папку
`dist/stage7-smooth/healthtracker`, включая `_internal`; её можно перенести целиком.
Бинарник запускается независимо от текущего рабочего каталога.
Рабочие `dist/stage7-chart-fix/healthtracker`, `dist/stage7-part3/healthtracker`, `dist/stage7-part2/healthtracker` и предыдущая `dist/healthtracker` сохранены и относятся к прежним версиям приложения.
Команда сборки выше заменяет только каталог `stage7-smooth`.

База: `$XDG_DATA_HOME/healthtracker/healthtracker.sqlite3` либо
`~/.local/share/healthtracker/healthtracker.sqlite3`.
Настройки: `$XDG_CONFIG_HOME/HealthTracker/HealthTracker.conf` либо
`~/.config/HealthTracker/HealthTracker.conf`. Данные находятся вне папки программы.
Копии создаются в выбранном пользователем каталоге, по умолчанию рядом с базой
в `backups`. Личные данные в поставку не входят.

Для безопасной автоматической приёмки на временных искусственных данных:

```bash
./dist/stage7-smooth/healthtracker/healthtracker --check-bundle
```

Этот режим сам изолирует XDG-пути, проверяет семь форм, графики, аналитику,
копирование/восстановление и повторный запуск отдельным процессом; затем удаляет
только свои временные данные. Обычный запуск без параметров открывает вашу базу.
Существующий `--smoke-test` проверяет график/WebChannel, но использует обычный путь
базы: для его испытаний задавайте отдельный `XDG_DATA_HOME`.

Системные зависимости, результаты проверки и ограничения —
[отчёт исправления](docs/stage7_chart_edges_report.md) и [BLACK HOLE](docs/stage7_part3_report.md) и [отчёт упаковки](docs/stage7_build_report.md). Проверена текущая Arch Linux x86_64;
универсальная переносимость между дистрибутивами не обещается. Ярлык меню и системный
пакет не устанавливались. Системный Python и пакеты при этой сборке не менялись.
